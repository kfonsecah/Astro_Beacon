# Codebase Concerns

**Analysis Date:** 2026-04-01

## Project Context

This is a **web-based visual reference** generated by Lovable (AI). It serves as a design blueprint for a React Native app called Astro Beacon. It has **no backend, no real data layer, and no authentication** — all data is hardcoded inline.

---

## What Cannot Be Directly Ported to React Native

### Heavy Reliance on Framer Motion Animations

**Files:** Every page and component uses `framer-motion` extensively
- `astro-beacon-reference/src/pages/Splash.tsx` — 60+ individually animated star particles with `Math.random()` inline
- `astro-beacon-reference/src/pages/Login.tsx` — 40 animated stars, blinking cursor, scanline overlay
- `astro-beacon-reference/src/components/space/ScanAnimation.tsx` — Expanding ring animations, particle burst
- `astro-beacon-reference/src/components/space/HudIndicator.tsx` — Sparkline with `Math.random()` per render
- `astro-beacon-reference/src/components/space/ResourceBar.tsx` — Per-segment animation with staggered delays

**Impact:** Framer Motion is DOM-only. React Native requires `react-native-reanimated` or `react-native-animatable`. Every `motion.div`, `motion.button`, and `motion.span` needs rewriting.

**Porting effort:** HIGH — ~80% of visual components use framer-motion. Key animations to replicate:
- Star field parallax (Splash, Login, Dashboard)
- Text glow pulsing (all HUD text)
- Scan line sweep (ScanAnimation)
- Progress bar fills (MissionProgress, Exploration)
- Staggered list entry animations (Bestiary, Logbook)
- Spring-based checkmark (LogResource success state)

### CSS-Only Visual Effects (No RN Equivalent)

**Files:** `astro-beacon-reference/src/index.css`

| CSS Class | Effect | RN Alternative |
|-----------|--------|----------------|
| `.text-glow-cyan`, `.text-glow-orange`, `.text-glow-green` | `text-shadow` multi-layer glow | Custom `<Text>` with shadow props or SVG overlay |
| `.border-glow`, `.border-glow-orange` | `box-shadow` with inset | `Shadow` props + custom border rendering |
| `.scanline` | `repeating-linear-gradient` overlay | Absolute positioned `<View>` with repeating pattern (SVG or image) |
| `.grid-pattern` | Dual `linear-gradient` background | SVG grid pattern or background image |
| `.flicker` | Keyframe opacity animation | `react-native-reanimated` withTiming |
| `.animate-pulse-glow` | Keyframe box-shadow pulse | Reanimated shared value loop |
| `::-webkit-scrollbar` | Custom scrollbar styling | Not applicable (RN ScrollView handles natively) |

**Impact:** ALL glow effects, scanlines, and grid patterns are CSS-only. These define the space theme aesthetic and must be recreated in RN.

### Tailwind CSS Utility Classes Everywhere

**Files:** All `.tsx` files use inline Tailwind classes exclusively

**Impact:** Tailwind doesn't work in React Native. Options:
- `nativewind` (Tailwind for RN) — closest match but has limitations with custom CSS variables
- `tailwind-react-native` — older, less maintained
- Manual StyleSheet conversion — most reliable but labor-intensive

**Critical patterns to replicate:**
- `bg-card/95 backdrop-blur-sm` — Semi-transparent cards with blur (RN: opacity + blur filter)
- `sticky top-0 z-30` — Sticky headers (RN: `stickyHeaderIndices` on ScrollView)
- `fixed inset-0` — Full-screen overlays (RN: `position: 'absolute'` with all edges 0)
- `grid grid-cols-4` / `grid-cols-3` — Grid layouts (RN: `flexWrap` or `FlatList` with `numColumns`)
- `max-w-lg mx-auto` — Centered content with max width (RN: `maxWidth` + `alignSelf: 'center'`)
- `border-t-primary/40` — Colored top borders with opacity (RN: `borderTopColor` + alpha)

### React Router DOM Navigation

**Files:** `astro-beacon-reference/src/App.tsx`, all page files

**Impact:** `react-router-dom` is web-only. React Native needs `@react-navigation/native` with stack/tab navigators. Route structure maps to:

| `/login` | LoginScreen | Stack |

| `/bestiary` | BestiaryScreen | Tab |
| `/species/:id` | SpeciesDetailScreen | Stack (pushed from Bestiary) |
| `/identify` | SpeciesIdentificationScreen | Stack (modal/full-screen) |
| `/resources` | ResourcesScreen | Tab |
| `/map` | ExplorationMapScreen | Stack (modal/full-screen) |
| `/exploration` | ExplorationScreen | Stack (pushed from map) |
| `/log-resource` | LogResourceScreen | Stack (pushed from exploration) |
| `/logbook` | LogbookScreen | Tab |

### Google Fonts via CSS Import

**File:** `astro-beacon-reference/src/index.css` line 1

```css
@import url('https://fonts.googleapis.com/css2?family=IBM+Plex+Mono:...&family=Space+Grotesk:...');
```

**Impact:** Fonts must be bundled as `.ttf`/`.otf` files and loaded via `expo-font` or `react-native` font linking. Two fonts needed:
- **IBM Plex Mono** — Used for all HUD text, labels, data values (`font-mono`)
- **Space Grotesk** — Used for body text, descriptions (`font-body`)

### DOM-Specific APIs

**Files:** Multiple
- `astro-beacon-reference/src/hooks/use-mobile.tsx` — Uses `window.matchMedia` and `window.innerWidth`
- `astro-beacon-reference/src/pages/SpeciesIdentification.tsx` — Camera viewfinder UI (no actual camera logic)
- `astro-beacon-reference/src/pages/LogResource.tsx` — `<input type="number">` and `<input type="text">`

**Impact:** All `window` API calls need RN equivalents. HTML `<input>` elements become `<TextInput>`.

## Performance Concerns

### Math.random() in Render

**Files:**
- `astro-beacon-reference/src/pages/Splash.tsx` — 60 stars, each with `Math.random()` for position, duration, and delay
- `astro-beacon-reference/src/pages/Login.tsx` — 40 stars with same pattern
- `astro-beacon-reference/src/components/space/HudIndicator.tsx` — 8 sparkline bars with `Math.random()` per render

**Impact:** In React, `Math.random()` during render produces different values on every re-render, causing visual jitter. In the web version this is masked by framer-motion's initial values. In RN, this would cause constant re-renders. Values should be memoized or computed once.

### Excessive Inline Animations

**File:** `astro-beacon-reference/src/pages/Splash.tsx`

60 `<motion.div>` elements each with independent `animate`, `transition`, and `style` props. Each creates its own animation loop. On low-end mobile devices, 60+ concurrent animations will cause jank.

**Fix:** Use a single canvas-based star field or reduce to ~20 stars with shared animation parameters.

### setInterval Without Cleanup Guards

**File:** `astro-beacon-reference/src/pages/Exploration.tsx`

```typescript
useEffect(() => {
  const interval = setInterval(() => {
    setProgress((p) => { ... });
    setO2((o) => Math.max(0, o - 0.2));
  }, 100);
  return () => clearInterval(interval);
}, [isComplete]);
```

The interval fires every 100ms updating two state values. If the component unmounts during the animation, the cleanup works, but the frequency (10fps) is excessive for a progress bar. Could be `requestAnimationFrame` or a slower interval.

## Fragile Areas

### Hardcoded Data Everywhere

**Files:** All page files

Every page uses inline arrays/objects for data. There is no abstraction layer, no types for domain models, no API client. When porting to RN, a data layer must be designed from scratch.

**Risk:** The reference UI creates expectations about data shapes (species have `id`, `name`, `type`, `status`, `description`, `habitat`, `danger`, `dangerLevel`, `notes`, `location`) that aren't formally typed.

### No Error Boundaries

**File:** `astro-beacon-reference/src/App.tsx`

No `ErrorBoundary` wrapping. If any component throws, the entire app crashes to a blank screen. The `NotFound` page only catches unmatched routes, not runtime errors.

### No Loading States

All pages render immediately with static data. In a real RN app with async data fetching, skeleton loading states are needed for:
- Bestiary species list
- Species detail
- Resource values
- Logbook entries
- Map points

### Sparkline is Random Noise

**File:** `astro-beacon-reference/src/components/space/HudIndicator.tsx` lines 33-39

```tsx
{[...Array(8)].map((_, i) => (
  <div key={i} style={{ height: `${Math.max(2, Math.random() * 12)}px` }} />
))}
```

The "sparkline" under each HUD indicator is pure random noise — it doesn't represent actual historical data. This is fine for a visual reference but shouldn't be replicated as-is in the RN app.

## Security Considerations

### No Authentication Logic

**File:** `astro-beacon-reference/src/pages/Login.tsx`

Any non-empty string passes "authentication." No password, no validation, no rate limiting. This is expected for a visual reference but the RN app needs real auth.

### No Input Validation

**File:** `astro-beacon-reference/src/pages/LogResource.tsx`

Quantity input accepts any number (including negatives and decimals) with no validation. Location field is a placeholder with no actual GPS capture.

### No Data Persistence

No `localStorage`, no database, no API calls. All state is ephemeral. The RN app needs to decide on persistence strategy (AsyncStorage, SQLite, Supabase, etc.).

## Critical Visual Elements to Replicate

These define the app's identity and should be prioritized in RN:

1. **Space color palette** — Deep navy background (`hsl(220, 68%, 11%)`), cyan glow primary (`hsl(160, 100%, 70%)`), destructive orange (`hsl(20, 100%, 70%)`), alien green accent (`hsl(100, 100%, 70%)`)
2. **Monospace typography** — IBM Plex Mono for all data/HUD text, tight letter-spacing
3. **Text glow effects** — Multi-layer text shadows on important values
4. **Scanline overlay** — Subtle horizontal line pattern on most screens
5. **Card design** — Dark cards (`hsl(240, 100%, 3%)`) with colored top borders and optional glow
6. **Bottom navigation** — 4-tab bar with icons + mono labels, active state glow
7. **Floating action button** — Pulsing radar button (bottom-right) to open map
8. **Star field background** — Animated twinkling dots on splash/login
9. **Progress bars** — Segmented resource bars with critical-state pulsing
10. **HUD indicators** — Compact stat displays with mini sparklines

## Optional Visual Elements

These enhance the reference but aren't critical for the RN app:

- Planet curvature on splash screen
- Crash trajectory animation on splash
- EKG line animation on dashboard
- Topographic contour lines on map
- Grid pattern overlays on map/identification screens
- Custom scrollbar styling (RN handles natively)
- `whileHover` effects on buttons (no hover on mobile)
