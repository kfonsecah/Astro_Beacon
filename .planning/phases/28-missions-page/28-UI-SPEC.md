## State & Interaction Design

### States per Component

| Component | Loading | Empty | Error | Success | Edge Case |
|-----------|---------|-------|-------|---------|-----------|
| Page root | Full-screen `ActivityIndicator` + "CARGANDO MISIONES..." | `EmptyState` component with icon + title + body | Centered error message + retry hint | Rendered FlatList + active panel | No active trip + no history → show empty state + INICIAR EXPEDICIÓN |
| Active mission panel | N/A (uses `useTripStore` which is synchronous) | Show "SIN MISIÓN ACTIVA" text | N/A | Show oxygen + duration + action buttons | `activeTrip` is `null` → hide panel entirely OR show "no active" state |
| Past missions list | Pagination spinner in `ListFooterComponent` | "SIN REGISTROS DE MISIÓN" (D-06) | Inline error per card if individual item fails | Cards with status badges, metrics, notes | Empty after reset (page 1 fetch in progress) — show loading state |

### Interactions

**INICIAR EXPEDICIÓN** (Primary CTA):
- Always visible on page (both empty state and below active panel)
- Navigates to new mission form: `router.push("/missions/new")` or `router.push("/app/missions/new")` (at agent's discretion)
- Form fields (from D-09): destino (lat/lng), presupuesto de oxígeno, notas

**COMPLETAR MISIÓN** (Active mission only):
- Calls `Alert.alert` with title "COMPLETAR MISIÓN" and body "La misión activa se marcará como completada. ¿Confirmar?"
- Cancel: "CANCELAR", Confirm: "COMPLETAR"
- On confirm: calls `useCompleteTrip({ id: activeTrip.id })` via mutation
- On success: `useTripStore.setState({ activeTrip: null })` — panel collapses, mission appears in history list
- Button disabled while mutation is pending, show "COMPLETANDO..." text

**ABORTAR MISIÓN** (Active mission only):
- Calls `Alert.alert` with title "ABORTAR MISIÓN" and body "Se perderá el oxígeno restante y el progreso de la misión actual. ¿Continuar?"
- Cancel: "CANCELAR" (style: 'cancel'), Confirm: "ABORTAR" (style: 'destructive')
- On confirm: calls `useAbortTrip({ id: activeTrip.id })` via mutation
- On success: `useTripStore.setState({ activeTrip: null })` — panel collapses, aborted mission appears in history list
- Button disabled while mutation is pending, show "ABORTANDO..." text

**Tap on past mission card** (D-13):
- `router.push(/missions/${item.id})` → read-only detail screen
- Requires creating `app/missions/[id].tsx` (read-only detail pattern, at agent's discretion whether existing `/trips` route is reused)

**Pull-to-refresh**:
- Past missions FlatList supports `RefreshControl` with `tintColor={tc.primary}`
- On refresh: reset page to 1, clear accumulated list, refetch

**Pagination** (from D-05):
- Accumulation pattern established in Phase 19: `useEffect` + `Set` deduplication
- FlatList `onEndReached` → increment page, append items
- `hasMore` guard based on `data.total > allItems.length`
