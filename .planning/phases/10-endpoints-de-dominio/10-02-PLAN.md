Create ResourceService class following auth.service.ts pattern:

**CRUD Operations (RES-01, RES-04):**
- create(userId, input): Create resource with category enum, apply default threshold if not provided
- findAll(userId, page, limit): Paginated list by userId
- findOne(userId, resourceId): Single resource or throw 404
- update(userId, resourceId, input): Update fields, preserve userId
- delete(userId, resourceId): Remove resource

**Movement Tracking (RES-02, RES-05):**
- recordMovement(userId, resourceId, input):
  - Validate resource exists and belongs to user
  - Calculate new amount: ingreso = +amount, egreso = -amount
  - Validate result >= 0 (no negative amounts)
  - Create movement record with previousAmount, newAmount
  - Update resource.currentAmount
  - Update resource.lastModified

**Alerts (RES-03):**
- getAlerts(userId): Find all resources where currentAmount < threshold
  - Only include resources that have a threshold set
  - Return resourceId, name, category, currentAmount, threshold, percentage

Use calculatePagination utility. Follow response patterns from auth.service.

Create resource controller following auth.controller.ts pattern:

**Endpoints:**
- GET /api/v1/resources — findAll with pagination (query: page, limit)
- GET /api/v1/resources/alerts — getAlerts
- GET /api/v1/resources/:id — findOne

- PUT /api/v1/resources/:id — update (body validation)
- DELETE /api/v1/resources/:id — delete

All endpoints require authenticate middleware. Use resourceSchema for validation.

Response envelope format:
```typescript
{

  data: result,
  pagination?: { page, limit, totalPages, hasNext, hasPrev }
}
```
