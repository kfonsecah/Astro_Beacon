<objective>
Corregir el bug de paginación sin acumulación en Bestiary, Logbook y Trips.

Bug actual: las tres pantallas asignan `data?.items` directamente a una variable local y la pasan
al `FlatList`. Cuando el usuario hace scroll y se carga la página 2, `data?.items` se actualiza
con solo los items de esa página, reemplazando los de página 1 en el FlatList.

El patrón correcto ya existe en `resources.tsx` (y `map.tsx`): estado local `allItems`, un
`useEffect` que acumula items nuevos usando un `Set` de IDs para deduplicar, y un `onRefresh`
que resetea el estado local completo.

Purpose: Hacer que las tres pantallas de lista con paginación infinita funcionen correctamente,
acumulando items al hacer scroll igual que `resources.tsx`.

Output: `bestiary.tsx`, `logbook.tsx` y `trips.tsx` con el patrón de acumulación aplicado.
</objective>

```typescript
const [page, setPage] = useState(1);
const [allResources, setAllResources] = useState<Recurso[]>([]);
const [hasMore, setHasMore] = useState(true);

const { data, isLoading, error, refetch } = useResources(page, 10);

useEffect(() => {
  const newItems = data?.items ?? [];
  if (newItems.length > 0) {
    setAllResources(prev => {
      const existingIds = new Set(prev.map(r => r.id));
      const filtered = newItems.filter(r => !existingIds.has(r.id));
      return filtered.length > 0 ? [...prev, ...filtered] : prev;
    });
    setHasMore((data?.total ?? 0) > allResources.length + newItems.length);
  }
}, [data]);

const loadMore = () => {
  if (hasMore && !isLoading && allResources.length < (data?.total ?? 0)) {
    setPage(p => p + 1);
  }
};

const onRefresh = async () => {
  setPage(1);
  setAllResources([]);
  setHasMore(true);
  await refetch();
};
// FlatList usa: data={allResources}
```
