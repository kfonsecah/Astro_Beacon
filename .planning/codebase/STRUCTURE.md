## Directory Purposes

**`app/`:**
- Purpose: expo-router file-based routing — every file is a route
- Contains: Screen components and layout definitions
- Key files: `app/_layout.tsx` (root navigator), `app/index.tsx` (home screen)
- **This is the primary source directory for the mobile app**

**`assets/images/`:**
- Purpose: Static image resources
- Contains: App icon, splash icon, Android adaptive icon components, favicon
- Key files: `icon.png`, `splash-icon.png`, `android-icon-foreground.png`

**`app-example/`:**
- Purpose: Expo default starter template — serves as pattern reference
- Contains: Example of proper expo-router structure, themed components, hooks
- **NOT part of the active app** — do not modify; use as structural guidance only

**`astro-beacon-reference/`:**
- Purpose: Lovable-generated web UI — design and component blueprint
- Contains: Full web application with 13 pages, 56 components, Vite tooling
- **NOT part of the React Native app** — adapt patterns/components for RN
- Key subdirectories: `src/pages/` (screens), `src/components/space/` (domain UI), `src/components/ui/` (primitives)

**`.planning/`:**
- Purpose: GSD (Get Shit Done) planning and codebase analysis documents
- Contains: ARCHITECTURE.md, STACK.md, and other planning artifacts
- Generated by `/gsd-map-codebase` commands

## Naming Conventions

**Files:**
- Route files: lowercase with hyphens or camelCase (e.g., `index.tsx`, `_layout.tsx`)
- Component files: PascalCase (e.g., `ResourceBar.tsx`, `SpaceCard.tsx`)
- Hook files: camelCase with `use-` or `use` prefix (e.g., `use-color-scheme.ts`, `useResources.ts`)
- Route group directories: wrapped in parentheses (e.g., `(tabs)/`, `(auth)/`)

**Directories:**
- Route groups: `(group-name)` for shared layouts without URL segment
- Component categories: lowercase descriptive names (`space/`, `ui/`)
- Feature directories: lowercase (`hooks/`, `services/`, `lib/`)

**Exports:**
- Default exports for route components (expo-router convention)
- Named or default exports for reusable components (reference uses default)

## Where to Add New Code

**New Screen/Route:**
- Create file in `app/[route-name].tsx` for a top-level screen
- Create file in `app/(group)/[route-name].tsx` for grouped screens
- Example: `app/(tabs)/dashboard.tsx` for a tab screen, `app/(auth)/login.tsx` for auth flow

**New Component:**
- Domain-specific: `components/space/[ComponentName].tsx`
- Generic UI: `components/ui/[component-name].tsx`
- Follow reference patterns from `astro-beacon-reference/src/components/`

**New Hook:**
- Location: `hooks/use[HookName].ts`
- Example: `hooks/useResources.ts`, `hooks/useOffline.ts`

**New Service/API Client:**
- Location: `services/[serviceName].ts` or `lib/api.ts`
- Example: `services/speciesClassification.ts`, `services/resourceSync.ts`

**New Utility/Helper:**
- Location: `lib/[utility].ts`
- Example: `lib/formatters.ts`, `lib/constants.ts`

**New Tests:**
- Location: Co-located `__tests__/` directory or `[file].test.ts` alongside source
- Reference pattern: `astro-beacon-reference/src/test/`

## Special Directories

- Purpose: File-based routing — directory structure = URL structure
- Generated: No — manually authored

**`astro-beacon-reference/`:**
- Purpose: Web UI reference generated by Lovable AI

- Committed: Yes — as design blueprint
- **Not imported or executed by the RN app** — purely reference material

**`app-example/`:**
- Purpose: Expo default template for structural guidance
- Generated: Yes — by `npx create-expo-app`
- Committed: Yes — as pattern reference
- **Not part of the active app** — do not modify

**`.expo/`:**
- Purpose: Expo generated types and cache (typedRoutes output)
- Generated: Yes — by `expo start` with `typedRoutes` experiment
- Committed: No — in `.gitignore`
